# 凭证组合来源与单边补齐设计

## 背景

凭证生成工作台已经能处理“银行流水 + 发票”的一一对应场景，也能为单边数据生成基础草稿。但真实做账中存在两类高频情况：

- 一对多 / 多对一：一张发票分多笔付款，或多张发票合并一笔付款。
- 单边数据：当月只有发票或只有银行流水，仍需完成当月记账和平账，并等待人工确认归属。

## 目标

让凭证工作台覆盖完整做账来源：

- 一对一匹配继续生成标准凭证。
- 一对多 / 多对一组合来源能生成一张凭证草稿。
- 单边发票按应收/应付生成待确认凭证。
- 单边流水按预收/预付/暂挂科目生成待确认凭证。
- 前端允许人工重新匹配，也允许在找不到另一边数据时按单边来源确认。

## 核心规则

### 发票无流水

- 销项发票：借记 `1122 应收账款`，贷记 `5001 主营业务收入` 与 `22210102 销项税额`。
- 进项发票：借记费用/成本科目与 `22210101 进项税额`，贷记 `2202 应付账款`。
- 状态保持 `PENDING_CONFIRMATION`。

### 流水无发票

- 银行付款：借记 `1123 预付账款`，贷记 `1002 银行存款`。
- 银行收款：借记 `1002 银行存款`，贷记 `2203 预收账款`。
- 若摘要明确是手续费，继续按 `560301 手续费` 处理。
- 状态保持 `PENDING_CONFIRMATION`，提示待补发票或确认业务归属。

### 一对多 / 多对一

- 使用 `source_data` 记录来源数组：`bank_transactions` 与 `invoices`。
- `source_key` 使用稳定组合 key，避免重复生成。
- 金额合计一致时生成组合凭证；差异过大则只保留单边待确认，不自动合并。

## UI 要求

- 凭证详情同时展示所有来源，不只展示第一条。
- 重新匹配弹窗支持：
  - 保留流水，选择一张或多张发票。
  - 保留发票，选择一笔或多笔流水。
  - 两边都重新选择。
  - 找不到另一边时，按单边来源生成待确认凭证。
- 被已确认凭证占用的数据仍展示但置灰。

## 验收

- 黛珂特 2026-04 凭证数应覆盖导入来源，不再只有少数一一对应凭证。
- 后端测试覆盖一对多、多对一、单边发票、单边流水。
- 前端测试覆盖组合来源显示、重匹配多选入口和单边确认入口。
- 浏览器中真实执行生成、刷新、查看凭证详情流程。
