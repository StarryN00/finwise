# 企业科技画像批量扫描设计

日期：2026-05-25
状态：待用户复核
目标项目：`finwise-accounting/`

## 1. 背景与目标

当前企业详情页已经支持单家企业粘贴企查查“科创分”弹窗文本，并解析为两类结构化数据：知识产权数量、科技型企业认定点亮项。这个入口适合校验解析口径和处理个别失败企业，但不适合真实业务中的批量查询。

下一阶段需要把科技画像做成可批量运行的常态化能力：系统按企业清单创建扫描任务，通过本机已登录的企查查或天眼查浏览器会话逐家查询，采集结构化结果并写回 FinWise。遇到验证码、登录失效、企业重名、未找到、页面结构变化等情况时，任务应安全暂停或标记为需人工处理，不应猜测或伪造标签。

本期目标不是实现贷款评分，而是为后续贷款评分沉淀可信的企业科技画像事实数据。

## 2. 设计原则

1. **批量优先，单家兜底**：正式工作流是批量扫描任务；企业详情页的文本导入保留为人工补录入口。
2. **事实采集与业务判断分离**：扫描只记录来源平台展示的事实，不在采集阶段生成“服务机会”或贷款评分。
3. **只保存企查查原生两大类结构**：企查查来源的结果按“知识产权”和“科技型企业认定”展示。
4. **不确定不入命中**：重名、缺少统一社会信用代码校验、页面证据不清晰时，标记为需人工处理。
5. **登录态本地化**：不把企查查/天眼查账号密码写入 FinWise 数据库，也不在日志中输出。
6. **可恢复**：批量任务应能从已完成企业之后继续，不重复写入已经采集的标签。

## 3. 数据来源与采集范围

### 3.1 支持来源

第一版支持两个来源：

- 企查查
- 天眼查

优先实现企查查，因为当前用户已经基于企查查“科创分”结构确认了字段口径。天眼查保留 provider 接口和任务来源枚举，后续实现独立适配器。

### 3.2 企查查采集结构

企查查采集结果只分两类。

**知识产权**

按企查查“知识产权取得情况”的分类采集数量：

- 有效发明专利
- 有效实用新型
- 有效外观设计
- 发明专利申请
- 软件著作权

后续如果企查查增加分类，可以在解析器中追加映射，但仍属于知识产权类别。

**科技型企业认定**

只采集企查查“科技型企业认定情况”中被点亮或明确匹配的项目：

- 科技型中小企业
- 高新技术企业
- 专精特新“小巨人”企业
- 专精特新中小企业
- 创新型中小企业
- 制造业单项冠军示范企业
- 制造业单项冠军产品企业
- 独角兽企业
- 瞪羚企业
- 雏鹰企业

未点亮项目不保存为标签。

### 3.3 不采集内容

本期不从扫描阶段生成：

- 服务机会
- 银行授信建议
- 贷款评分
- 未展示在来源平台上的推断标签

这些内容后续由融资评分或服务策略模块基于已确认画像另行计算。

## 4. 批量扫描流程

### 4.1 任务入口

在企业名册增加批量扫描入口，支持以下范围：

- 全部企业
- 未扫描企业
- 需复查企业
- 扫描失败企业
- 当前勾选企业

第一版默认推荐“未扫描企业”和“当前勾选企业”。

### 4.2 任务创建

创建任务时记录：

- 来源平台：`QICHACHA` 或 `TIANYANCHA`
- 扫描范围
- 企业数量
- 操作人标识
- 创建时间
- 任务状态

任务状态：

- `PENDING`：待运行
- `RUNNING`：运行中
- `COMPLETED`：全部完成
- `PARTIAL_FAILED`：部分完成，部分需人工处理或失败
- `FAILED`：任务整体失败
- `PAUSED`：遇到验证码、登录失效或用户中断

### 4.3 单家企业扫描状态

每家企业在任务中有独立明细状态：

- `PENDING`：待扫描
- `RUNNING`：扫描中
- `COMPLETED`：已完成并写回
- `NEEDS_REVIEW`：需要人工处理
- `FAILED`：失败
- `SKIPPED`：跳过

失败或复核原因：

- `LOGIN_REQUIRED`：未登录或登录失效
- `CAPTCHA_REQUIRED`：触发验证码
- `AMBIGUOUS_MATCH`：搜索结果重名或无法确认主体
- `NOT_FOUND`：未找到企业
- `NO_INNOVATION_PANEL`：未找到科创分或对应弹窗
- `PAGE_STRUCTURE_CHANGED`：页面结构变化导致无法解析
- `PROVIDER_RATE_LIMITED`：来源平台访问受限
- `UNKNOWN_ERROR`：未知错误

### 4.4 采集步骤

1. 从 FinWise 获取任务企业清单。
2. 使用本机已登录浏览器打开来源平台。
3. 按企业全称搜索。
4. 如果能取得统一社会信用代码，则用信用代码校验主体。
5. 进入企业详情页。
6. 打开科创分或同等科技画像入口。
7. 提取知识产权分类数量和科技型企业认定点亮项目。
8. 调用 FinWise API 写回结构化扫描结果。
9. 更新单家企业扫描状态。
10. 继续下一家企业。

### 4.5 人工中断与恢复

遇到登录、验证码、短信验证、平台风控时，采集器停止继续访问，并将任务标记为 `PAUSED`。已完成企业保留结果，未完成企业保持 `PENDING` 或记录具体失败原因。用户处理登录或验证码后，可以继续同一任务。

## 6. API 设计

新增或完善以下接口：

- `POST /api/technology-scan-jobs`
  - 创建批量扫描任务。
- `GET /api/technology-scan-jobs`
  - 查询任务列表。
- `GET /api/technology-scan-jobs/{job_id}`
  - 查询任务详情和企业明细。
- `POST /api/technology-scan-jobs/{job_id}/items/{item_id}/mark-running`
  - 采集器标记单家企业开始处理。
- `POST /api/technology-scan-jobs/{job_id}/items/{item_id}/complete`
  - 采集器提交单家企业结构化结果，并写回画像。
- `POST /api/technology-scan-jobs/{job_id}/items/{item_id}/fail`
  - 采集器提交失败原因。
- `POST /api/technology-scan-jobs/{job_id}/pause`
  - 遇到验证码、登录失效或用户中断时暂停任务。

现有接口继续保留：

- `GET /api/enterprises/{enterprise_id}/technology-profile`
- `POST /api/enterprises/{enterprise_id}/technology-profile/scan-results`
- `POST /api/technology-tags/{tag_id}/confirm`
- `POST /api/technology-tags/{tag_id}/reject`

- 勾选企业
- 批量扫描科技画像
- 查看最近扫描任务

科技画像列继续显示：

- 状态
- 命中的科技型企业认定

### 7.2 科技画像任务抽屉或页面

新增任务查看界面，第一版可以作为企业名册中的抽屉：

- 任务状态
- 来源平台
- 企业总数、已完成、失败、需复查
- 每家企业状态

### 7.3 企业详情

## 8. 采集器设计

第一版采集器是本地脚本或 Codex skill 驱动，不内嵌在 FastAPI 后端。

原因：

- 企查查和天眼查需要登录态。
- 可能出现验证码、短信验证、平台风控。
- 使用本机浏览器会话更容易让用户介入处理。
- 后端保持稳定的任务队列和入库接口，不承担平台自动化风险。

采集器职责：

- 读取待扫描任务。
- 操作已登录浏览器。
- 从页面提取文本或结构化 DOM。
- 调用后端 API 更新任务状态和画像结果。
- 遇到人工验证时暂停任务。

采集器不负责：

- 保存账号密码。
- 绕过验证码。
- 猜测企业主体。
- 推导服务机会或贷款评分。

## 9. 审计与数据质量

每个写回标签必须保留：

- 来源平台
- 来源链接
- 证据文本
- 采集时间
- 可信度

如果匹配主体不确定，不写入命中标签，只记录任务明细为 `NEEDS_REVIEW`。

如果同一企业重复扫描，采用幂等 upsert：

- 同一来源、同一分类、同一标签名更新原记录。
- 不重复创建同名标签。
- 未点亮标签不写入，也不主动删除历史已确认标签；历史标签是否失效需要后续“复扫过期处理”规则决定。

## 10. 测试策略

### 10.1 后端测试

- 创建批量扫描任务时按范围生成任务明细。
- 任务明细可以从 `PENDING` 转为 `RUNNING`、`COMPLETED`、`NEEDS_REVIEW`、`FAILED`。
- 单家完成时写回 `TechnologyProfile` 和两类 `TechnologyTag`。
- 重复提交同一企业结果不生成重复标签。
- 失败原因能正确保存并体现在任务统计中。
- 暂停任务后不影响已完成企业。

### 10.2 前端测试

- 企业名册存在批量扫描入口。
- 勾选企业后可以创建扫描任务。
- 任务抽屉展示总数、已完成、失败、需复查。
- 任务明细展示失败原因和企业详情入口。
- 企业详情仍保留单家文本导入入口。

### 10.3 采集器测试

- 使用本地样本文本验证企查查解析器。
- 使用模拟任务 API 验证采集器状态流转。
- 模拟验证码/登录失效时，任务进入 `PAUSED`，未完成企业不被误标完成。
- 不在日志输出账号、密码、Cookie、原始 HTML。

## 11. 第一版交付范围

第一版交付以下能力：

1. 后端批量任务和任务明细模型。
2. 批量任务 API。
3. 企业名册批量创建任务入口。
4. 任务详情抽屉或页面。
5. 本地采集器脚本骨架，支持读取任务、提交结果、标记失败和暂停。
6. 企查查文本解析继续沿用当前两大类结构。
7. 全量测试与一次本地页面验收。

第一版不交付：

- 完整无人工干预的后台爬虫。
- 验证码绕过。
- 贷款评分。
- 服务机会自动生成。
- 天眼查完整解析适配。

## 12. 自检结论

- 本规格聚焦批量科技画像扫描，没有混入贷款评分实现。
- 采集数据口径与用户确认一致：知识产权数量、科技型企业认定点亮项。
- 保留单家文本导入作为失败兜底，但不作为主流程。
- 已明确验证码、登录失效、重名等高风险场景的处理方式。
- 没有使用“服务机会”作为扫描结果。
