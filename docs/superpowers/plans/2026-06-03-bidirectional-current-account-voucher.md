# 双向往来未开票凭证处理开发计划

## 目标

把同一交易对方在同一月度工作包中同时出现收款和付款、且暂无发票匹配的银行流水，从普通“单边处理”中识别出来，按“往来款暂挂”生成待确认凭证。

## 范围

1. 后端凭证生成
   - 识别未匹配银行流水中同一对方同时存在收款和付款的场景。
   - 收款暂挂到 `2241 其他应付款`。
   - 付款暂挂到 `1221 其他应收款`。
   - 在 `source_data` 写入 `source_group_type=BIDIRECTIONAL_CURRENT_ACCOUNT` 和 `accounting_treatment`，保留交易对方作为辅助核算依据。

2. 前端凭证生成工作台
   - 对双向往来场景展示“双向往来未开票 / 往来款暂挂”。
   - 继续允许用户通过“调整处理方式”改成其他会计处理。
   - 来源状态筛选和来源组标签使用中文显示。

3. 测试与审计
   - 增加后端回归测试，覆盖同一对方收付双向无发票时的科目推荐。
   - 增加或更新前端源代码测试，覆盖中文标签和处理方式展示。
   - 跑后端、前端相关测试；必要时用浏览器验证页面状态。

## 非目标

- 本次不自动创建“其他应收款-对方名称”这类明细科目。
- 本次不改账套辅助核算模型，只在 `source_data.accounting_treatment` 中记录对方名称。
- 本次不做历史账龄、合同、发票后续冲销的完整流程。

## 验收点

- 同一对方只有流水、无发票，且有收有付时，不再默认进入预收/预付。
- 付款凭证分录为：借 `1221 其他应收款`，贷 `1002 银行存款`。
- 收款凭证分录为：借 `1002 银行存款`，贷 `2241 其他应付款`。
- 前端详情中能明确看到“往来款暂挂”及原因。
- 测试通过，并且没有引入 `[object PointerEvent]` 一类事件参数路径问题。
