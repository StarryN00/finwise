# 第2、3步 Codex 最小实验

## 执行前固定的验收目标

输入为用户提供的原始资料，以1—7月为基准，处理8月已有账务。Agent 自主识别资料用途、制定并更新工作计划、读取及计算、调查历史关联、核查已有会计处理，输出可供第4步复核的候选分录及真实待决事项。提供了当月原账，因此不是无原账条件下的做账盲测。

任务与调查项目必须从资料产生。提示词不得含上次交付的问题清单、已知金额、笔数、结论或分析代码。此次无需重新生成精装 Excel/PDF 交付包。

采用本机 Codex CLI + 当前配置的模型，工作目录只放原件副本、通用读取/金额校验工具和交付契约。使用 workspace-write 沙箱；禁止读取历史实验、应用数据库、密钥或其他工作区；禁止改原件和冻结工具。原件哈希、工具、提示词、模型版本、JSONL 事件和每轮成果均保留。

执行 Agent 必须维护可追溯的计划、已解决问题、未解决问题和下一步，遇到工具错误自行恢复。外层系统运行确定性检查，并以独立 Codex 会话重新检查原件和成果；审查结论必须包含具体证据，模型同意不等于事实验证。检查失败自动反馈执行 Agent，最多3轮；超限归系统受阻，不归用户确认。

## 完成条件

- 原件均有用途、处理范围与来源定位；本期既有分录完整重建，金额/科目/日期不因核验而篡改。
- 期初衔接、凭证借贷、银行及发票覆盖由程序另行重算。识别一致仅证明读取或算术一致。
- 每张候选凭证有业务解释、证据、适用限制与待决事项；证据不足的候选不得标为可确认。
- 对来源之间的冲突与缺失依据，优先调查已有资料。人工问题必须说明查过什么、仍缺什么、影响哪些凭证。
- 独立审查从原件重新寻找遗漏，验证重要结论，不仅检查执行 Agent 自报的清单。
- 区分处理能力验收与第4步接入验收。隔离数据库接收已验证成果，在复核界面展示原分录、证据和限制；不得伪造现有采购流程的已确认业务组/规则来通过入口。
- 正式账、旧实验、原件不变；无人工中途补数据、提示个案答案或修改冻结执行程序。

## 边界

独立审查、确定性检查和适配器均保留独立结果。实验运行完成不代表财务定稿、用户已复核或正式过账。当前生产第4步的通用适配能力若不足，须报告具体接口缺口，不能通过改阶段标志伪装成功。
