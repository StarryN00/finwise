# ActionType 对象化与引导式工作台规格审查

审查范围：`docs/task-action-types-and-guided-ux.md` 的阶段 1 与阶段 1.5，以及用户确认的安全边界。

## 结论

规格审查通过。审查发现的 1 项权限一致性问题已修复：管理员没有更高角色可转交，因此 `escalate` 的声明权限收紧为业务员和会计，前端按声明禁用，服务端仍做权限校验。修复后 P0/P1/P2 未见遗留项。

## 规格对照

- `ontology-v1.3` 公开只读 ActionType 目录，包含版本、谓词、证据要求、`FieldDescriptor` 字段、决策输入、结构化效果、权限、撤销入口和兜底标识。
- `classify_task` 改为标准化上下文和有序声明式规则。16 个旧路由特征化用例锁定了 PARSE、红蓝票、票据、银行、期间、金额、空日期、VERIFY 和 SYSTEM 门禁。
- 原件失效、绑定/定位不完整、对照不安全、解析未完成优先进 SYSTEM；只有通过这些门禁且未匹配专用动作的事项才获得 5 个兜底动作。
- 5 类未知问题的自动测试全部进入人工队列，无需新增分类代码；每项均获得 `record_judgement`、`suspend`、`request_supplement`、`mark_out_of_scope`、`escalate`。
- 5 个兜底动作都通过 `/commands` 执行，绑定任务/原件/记录版本和描述符指纹，支持幂等、撤销、失效投影和审计。
- 兜底动作的效果全部声明 `grants_accounting_usable=false`；专项测试确认不修改原件、事实、业务组、正式凭证和期间。
- `mark_out_of_scope` 允许业务员、会计、管理员；已进入下游组的记录会被拒绝，生效决定也会阻止新建候选组。
- `decision-v2` 增加 `stage`、`why_now` 和结构化效果，`decision-v1` 仅保留只读展示。成功命令及幂等重放都返回当前 `next`。
- 工作台首屏保留问题、原值/提取值对照和下一步；次要统计、处理记录、方法口径默认收起。统计均有下钻动作，活跃界面只有一个主按钮，对话框打开时背景主按钮隐藏且不可操作。
- `action_metrics` 只统计当前 Scope 内成功执行的已声明动作，返回总数、兜底数、占比和逐命令下钻记录。
- 阶段 2 只保留 `ACTION_TYPE_CANDIDATE_REQUESTED` 审计契约，未实现对话层、模型创建动作或自动审批。
