# ActionType 对象化与引导式工作台质量审查

审查范围：阶段 1 与阶段 1.5 的服务端目录、任务路由、命令执行、工作台交互、测试、隔离回放和交付边界。

## 结论

质量审查通过。最终复核未发现 P0、P1 或 P2 遗留问题；本轮发现的权限一致性、旧契约兼容和个人任务隔离问题均已修复并由测试覆盖。

## 已发现并修复的问题

- `escalate` 最初对管理员可见，但管理员不存在可转交的更高角色。现已统一收紧为业务员和会计可用，目录声明、前端可用性与服务端授权保持一致；管理员执行会明确拒绝。
- `decision-v2`、命令 `next` 和默认收起区改变了旧测试夹具的契约。相关测试已按公开契约更新，同时保留 `decision-v1` 只读展示，未给旧决定开放写入。
- 个人资料引导任务的查询原先可能混入其他操作人的意见任务。现已按当前操作人拥有的意见编号隔离，并纳入完整回归。
- 任务草稿的异步刷新原先可能覆盖用户已编辑的 ActionType 表单。导航层现将 `taskAction` 纳入修订判断，迟到响应不再清除编辑内容。
- 固定分支对比脚本在中文紧邻变量和临时工作区清理处存在执行器问题。现只修复变量边界和清理目录，不改变任何验收门槛。

## 代码与边界审查

- ActionType 是只读、版本化声明，未建立第二条解析或财务写入链路；专用动作继续调用既有处理入口。
- 五个兜底动作只创建或撤销 `Decision`，所有结构化效果均为 `grants_accounting_usable=false`。
- `mark_out_of_scope` 只投影当前任务和候选分组状态；发现正式下游记录时拒绝执行，不删除原件或事实。
- 未知谓词失败关闭，安全门禁优先于通用兜底，版本、权限、字段、幂等和描述符指纹均在服务端复核。
- 成功命令和幂等重放均由当前工作台状态计算 `next`，没有缓存旧的下一事项。
- `action_metrics` 的分母仅包含当前账套期间内成功执行且仍在目录声明的任务动作，明细可下钻。
- 阶段 2 只保留候选动作审计事件，没有引入对话生成、模型审批或自动执行。

## 已知限制

- 项目虚拟环境没有安装 `pip`，因此无法执行 `pip check`；这不影响已经运行的完整 Python 测试，但依赖元数据未由该命令再次核验。
- `/Volumes/共享文件夹` 本轮未挂载，聚贤达回放使用 Staging 中保留且哈希校验通过的原件副本，不是从外接盘现场重新导入。
- ActionType 写入浏览器验收使用真实页面和真实点击，但网络端由确定性测试夹具响应；服务端命令行为另由 Python 集成测试覆盖。本轮没有向真实财务数据发出写命令。
