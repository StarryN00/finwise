# 资料处理 Agent 执行循环

本次将发票最小试验接入实际资料工作台。范围是本期业务原件的读取、核验、重读修复、相关资料检索与问题交接；期初、记账、凭证审批和交付沿用已有业务门禁。

## 行为

用户在本期点击“开始自动处理”后，服务器建立持久化授权范围和每份原件的执行任务。模型每轮选择一个受控工具，服务端执行并保存结果，再把脱敏结果交给下一轮。刷新或重新打开网页只读取状态，不启动模型。

工具包含：查看来源、核验提取、重读、保存已核验候选、查找本期相关资料、整理未决问题、完成、记录阻塞。完成必须满足当前已存结果通过核验、已查相关资料、已整理事项且没有未保存候选。模型不能以文字宣称通过，也不能直接写 SQL 或正式财务对象。

- 相同结果重读不产生业务版本，不使已有确认失效。
- 真正修复通过现有解析执行器生成版本、失效旧依赖并记录审计；保存后必须再核验。
- 任务和每步结果落入现有 SQLite 对象/审计存储。进程重启后回收过期执行租约，继续处理；模型调用可能重复，不承诺费用恰好一次。
- 来源、事实、人工决定、意见及建议结果变化会使旧结论失效并生成新任务。原任务留档。用户的暂缓、排除本期、等待材料等有效决定会被重新读取。
- 原件、读取字段、解析器、版式和账户映射未变化时，业务意见或相关材料变化可复用来源核验证明，但必须重新检索相关资料、整理未决事项；来源依赖变化立即使该证明失效。
- 默认每轮最多 12 步，连续三次相同工具无进展则暂停。模型传输/JSON 故障最多自动重试两次并退避；仍失败则保留进度，网页可继续。
- 未完成核验的原件不向用户推送整表确认。读取问题保持系统受阻；已核验来源只有明确的业务事项进入原有受控人工入口。

## 证据与边界

核验从本地原件重新建立完整字段、锚点、派生值、警告及期间契约；枚举非空及纯公式行，阻止解析器静默漏行。税局汇总页需与发票基础页逐发票核对身份、日期和金额，不能直接忽略。银行重读保留已确认账户绑定，并沿用版式解析规则。

原件身份字段仅在本地处理。工具模型收到状态、数量、字段名和检查代码；新模式下原有办理建议也使用脱敏输入。金额相同只说明找到候选，不会自动认定发票已经付款。

当前确定性核验主要覆盖支持的表格原件。扫描 PDF、未知布局、公式无法独立验证或专用工资/结构方案无法安全重放时，保留具体系统阻塞；不能以模型置信度替代核验。这些格式能力仍需后续实现，不代表完整会计自动化已完成。

## 配置与接口

`Settings.from_env()` 默认启用 `FINWISE_AGENT_LOOP_ENABLED=true`；`FINWISE_AGENT_LOOP_MAX_STEPS=12`，允许 4–30。真实执行使用现有 Gateway 配置与推理模型，不另存密钥。初次开始后，后台持续检查已授权范围内的输入变化。

- `POST /api/v1/materials/process`：请求体 `{ "scope": ... }`。
- `POST /api/v1/materials/process/{job_id}/resume`：显式继续受阻/失败任务，同样传范围。
- `POST /api/v1/workbench`：`material_review.agent_processing` 返回来源状态、证明摘要和执行轨迹。

沿用登录、角色和范围授权；后台每步写入前重新检查操作账号及期间权限。设置 `FINWISE_AGENT_LOOP_ENABLED=false` 并重启可关闭新流程，保留执行记录；不要用旧数据库覆盖新产生的人工决定。

## 扫描 PDF 的本地 OCR 补充（2026-09-22）

可选安装：`uv pip install --python .venv/bin/python -e '.[pdf-ocr]'`。本机已安装 RapidOCR 3.9.2 与 ONNX Runtime CPU，使用 PP-OCRv4 mobile 中英模型；首次需下载公开模型权重，客户扫描件不上传。依赖加模型实际占用需与运行环境一起测量，不能只按 Python 包体积估算。

执行器在 SQLite 写事务外运行 OCR，逐页保存文本框与识别分数，数字格式异常时局部裁剪并用英文数字识别模型重读，保留前后读数。支持范围是已验证表头的江苏银行扫描对账单，每页单图、最多 10 页、每页不超过 2000 万像素；未知版式、多图页、加密页明确阻断，不默默忽略。

这是一条补充读取证据路径：比较现有事实，检查笔数、借贷合计、期末余额和余额连续性。即使金额全部通过，也不自动覆盖日期、摘要、对方信息，不把 OCR 置信度当作原件已核验。本版 OCR 结果始终保留系统受阻，直到具体差异由后续核验执行器解决；因此不是完整的 PDF 自动解析入账功能。

本机真实结果：2 页、35 行，6 项金额与余额检查通过；245 个比较字段中 212 项一致、33 项存在分歧。第 9 行 OCR 为 2026-09-03，旧读数为 2026-09-02，表头期间为 8 月。原值保留，未用表头月份改日期。识别/比对证据在 `output/pdf-ocr/`，不得提交客户资料。

选型来源：[RapidOCR](https://github.com/RapidAI/RapidOCR)、[pdfplumber](https://github.com/jsvine/pdfplumber)、[pypdfium2](https://github.com/pypdfium2-team/pypdfium2)。本次选择本地 RapidOCR；已有 pypdf 可提取该文件的整页图，不额外引入 PDF 渲染器。pdfplumber 不负责扫描图像 OCR，未为这份文件安装它。

本轮全量回归 1,266 项通过；实际工作台已刷新验收，PDF 显示 35 条读取、33 处差异及具体日期问题。所有非 Agent 业务对象与运行前备份一致。
