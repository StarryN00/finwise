# 月度自主处理最小实验

## 冻结目标（执行前）

以1—7月为基准处理8月。输入仅为用户指定的7份原始文件；不输入上一轮成果、分析脚本、问题清单或已读取的OCR结果。后台任务从启动到交付之间，不由用户或开发助手补数据、执行分析、修改模型代码或点击继续。

本实验验证“已有月账的自主重建、跨资料复核、成果及真实缺口交付”，因为输入包括8月序时账与余额表；不将此结果当成仅凭票据流水独立做账的盲测。

## 验收

1. 一次启动后，真实模型自主选工具、读取工作表、使用受限Python进行分析、对扫描件使用新执行的OCR及视觉复查；完整轨迹落库。工具出错反馈给同一任务，允许自动纠正。
2. 从源文件重建完整8月分录，验证凭证平衡、7月衔接、8月余额、银行连续余额和发票去重。金额核验由服务端独立执行，不能由模型自报成功。
3. 主动跨历史查证承兑与销售的账务关联，识别原件期间矛盾、跨月费用和缺少底层依据的结转。保留原值，不为完成而猜填。
4. 形成持久化的候选凭证、试算、发票与流水、未决事项和处理记录，可在系统页面查看。正式账务、期间状态和既有业务对象不变。
5. 使用隔离数据库和原件副本。启动后冻结程序版本和输入指纹；若必须修代码或人工提示才完成，该次为失败，另起新运行，不伪装成原运行自主成功。

## 最小实现边界

复用现有FastAPI、Scope、原件存储、版本化对象和模型网关。新增月度任务及受限计算工具：计算工具只能读取当前任务已提供的表格/读取观察和自己的工作状态，没有文件、网络、SQL、进程操作能力。模型可写分析代码并改错，不能写正式财务对象。

候选成果单独保存为MonthlyAgentDelivery，用户可审阅；这次不扩展正式过账和申报，也不把原系统第4阶段机械标为完成。

## 运行方式与恢复

实验开关 `FINWISE_MONTHLY_AGENT_ENABLED` 默认关闭，原服务不会自动启用新任务。专用启动器使用独立数据库，绑定本机8771端口：

```sh
.venv/bin/python scripts/start_monthly_pilot.py --attempt 2
```

通过现有原件接收接口将原文件存入该隔离环境，在 `/static/monthly-experiment.html` 选择企业、期间和原件，点击一次“开始月度自主处理”。刷新页面只读取进度。相同版本和输入重复启动返回同一个任务；任务进度、计算状态和模型调用记录持久化到数据库。工作进程中断后，租约过期可由同版本进程接续；程序版本变化则停止旧任务。

`output/monthly-agent-pilot[-N]/` 保存该轮数据库、文件清单、启动前对象快照、冻结代码副本和独立验收结果。该目录被Git排除，客户原件及成果不得提交到仓库。

## 第一轮：失败记录

第一轮使用v1执行器，完成19步后由实验验收方终止，未生成候选交付。不能将这一轮称为自主成功。

观察到的执行器缺陷：历史只反馈工具结果，遗漏刚执行的代码；模型遇到错误后无法直接复用原代码修正。计算环境不提供type以及惯用的decimal/json导入，造成重复兼容性错误。一次视觉观察还出现了与OCR行金额不一致的判断，说明不能凭视觉模型自信程度改写原值。

第二轮v2只修正通用执行能力：回传上次调用代码和错误行号，开放限定的纯计算库及常用函数，允许保存工作计划；原始日期与建议修正分开保留。第一轮的任何中间分析、问题答案、候选结果都未作为第二轮输入。第二轮仍从原件重新开始，并再次冻结程序和输入。
