# FinWise 第一期 关键字段与流程断点清单

> 用途：依赖代账公司资料时，确保关键字段不缺，流程不断
> 更新日期：2026-05-09

---

## 流程总览

```
企业创建 → 发票导入 → 流水导入 → AI解析 → 发票匹配 → 报告生成 → Dashboard
   ↓           ↓           ↓          ↓          ↓           ↓            ↓
 必填        必填        必填      必填      必填        必填         必填
高风险      高风险      中风险     中风险    高风险      中风险       低风险
```

**流程断点**（任何一个断掉，后面全走不下去）：
1. 企业创建失败 → 全系统无法使用
2. 发票导入失败 → 无法匹配，VAT 报告无法生成
3. 流水导入失败 → 无法 AI 解析，无法匹配
4. AI 解析失败 → 无法匹配，流水状态死在 PENDING
5. 发票匹配失败 → 匹配结果空白，报告数据不准确
6. 报告生成失败 → 报告下载空白/报错

---

## 一、企业创建（前端界面 → POST /api/enterprises）

### 关键字段（缺一个都不行）

| 字段 | 为什么必须有 | 缺失后果 |
|------|------------|---------|
| `name` 企业名称 | 主键，所有报告的文件名都用它 | 报告下载文件名异常 |
| `unified_social_credit_code` 统一社会信用代码 | 企业唯一标识，用于去重 | 可能导致重复企业 |
| `taxpayer_type` 纳税人类型 | 决定 VAT 税率计算（13% vs 3%） | 税额计算错误 |
| `industry` 所属行业 | 用于 Dashboard 行业分布图 | 行业图表显示为空 |

### 非关键字段（缺了没大问题）

| 字段 | 缺了怎么办 |
|------|------------|
| `registered_capital` 注册资本 | Dashboard 不显示，融资评分时不参考 |
| `establishment_date` 成立日期 | 不影响主流程 |
| `province` / `city` | 不影响 |
| `source` 企业来源 | 筛选功能不可用 |
| `status` | 默认 ACTIVE |

---

## 二、发票导入（POST /api/imports → backend/routers/parse.py）

### 关键字段（缺一个都不行）

| 系统需要的列名 | 代账表格里可能叫 | 缺失后果 |
|----------------|------------|---------|
| `invoice_number` | 发票号码 / 发票代码 / 发票编码 | 行被跳过，发票丢失 |
| `invoice_type` | 发票类型 / 类型 | 系统无法分辨进/销项，税额计算错误 |
| `issue_date` | 开票日期 / 日期 | 该发票被跳过，空白日期无法匹配和计算 |
| `amount` | 金额 / 不含税金额 | 发票计算错误，VAT 报告不准 |
| `tax_amount` | 税额 / 税款 | 税额计算错误（系统会尝试自计算，但可能不准） |
| `total_amount` | 价税合计 / 总金额 | 匹配时以此为准，缺失无法金额匹配 |

### 重要但非必填字段

| 字段 | 缺了会怎么样 | 建议 |
|------|------------|------|
| `seller_name` 销售方名称 | 匹配时无法做名称关联，AI 解析差 | 有就留着，没有也能跑 |
| `seller_tax_number` | 不影响主流程 | 可以缺 |
| `buyer_name` / `buyer_tax_number` | 不影响主流程 | 可以缺 |

### 特别注意

1. **发票号重复**：同一企业同一发票号只会导入一次，重复的会被跳过
2. **发票类型必须正确**：必须是 "进项" 或 "销项"，写成 "进" / "销" / "进货" 等可能被误识别
3. **日期格式**：支持 `2026-04-15`、`2026/4/15`、`2026.4.15`、`15/04/2026` 等
4. **金额格式**：支持含千分位符和币种符号

---

## 三、银行流水导入（POST /api/imports → backend/routers/parse.py）

### 关键字段（缺一个都不行）

| 系统需要的列名 | 代账表格里可能叫 | 缺失后果 |
|----------------|------------|---------|
| `transaction_date` | 交易日期 / 日期 / 交易时间 | 行被跳过，流水丢失 |
| `summary` | 摘要 / 交易说明 / 用途 | 无法 AI 解析，无法匹配 |
| `debit_amount` 或 `credit_amount` | 借方金额 / 贷方金额 / 支出金额 / 收入金额 | 无法匹配，AI 解析无法判断金额 |

### 重要但非必填字段

| 字段 | 缺了会怎么样 | 建议 |
|------|------------|------|
| `balance` 余额 | 前端显示为 - | 不影响主流程，有就留着 |
| `counterparty_name` 对方户名 | 匹配时无法做名称关联 | 有就留着，没有也能跑 |
| `counterparty_account` | 不影响 | 可以缺 |

### 特别注意

1. **流水里必须有借方或贷方金额**：至少有一个有值，两个都是 0 则跳过
2. **金额应与发票价税合计对齐**：例如发票 total_amount=11300，流水借方金额应为 11300
3. **日期差 ≤ 7 天**：发票开票日期与流水交易日期差 7 天内才会被匹配算法考虑

---

## 四、AI 解析（前端点击 "AI 解析" → 后端调用 AI API）

### 这一步不需要你准备任何额外数据

- 系统会自动调用 AI 解析流水的 `summary` 字段
- 解析结果写入 `parsedTransactions` 字段
- **断点风险**：如果 AI API 异常（网络问题、API Key 失效），流水状态死在 PENDING，无法继续后续流程

---

## 五、发票匹配（POST /api/match → 后端匹配算法）

### 这一步不需要你准备额外数据

- 系统自动根据金额 + 日期 + 关键字匹配
- **匹配逻辑层级**：
  1. 金额完全相等 + 日期差 ≤ 3天 → 精确匹配（级别最高）
  2. 金额相等 + 日期差 4-7天 → 模糊匹配
  3. 金额相等 + 关键字匹配 → 关键字匹配
  4. 无法匹配 → 未匹配

### 如何确保匹配成功

| 你需要确保 | 为什么 |
|------------|------|
| 发票的 `total_amount` = 流水的 `debit_amount` | 金额匹配是第一先决条件 |
| 发票日期与流水日期差 ≤ 7 天 | 超过则不会被匹配算法考虑 |
| 流水摘要含有 "货款" / "服务费" / "租金" 等 | 关键字匹配会提高匹配率 |

---

## 六、报告生成（POST /api/reports → 后端报告生成器）

### 不需要你准备额外数据

- 系统自动根据导入的发票 + 匹配结果 + 企业信息生成
- **断点风险**：如果没有导入发票，报告会显示空白/零值

### 各报告的依赖关系

| 报告类型 | 依赖的数据 | 缺少数据的后果 |
|----------|------------|------------|
| VAT 税务报告 | 发票（进项+销项） | 报告为空，税额计算错误 |
| 财务健康报告 | 发票 + 流水 | 某些指标为空（如现金流指标） |
| 融资评分报告 | 发票 + 流水 + 企业信息 | 评分偏低或某些指标为空 |

---

## 七、Dashboard 数据汇总（GET /api/dashboard/summary）

### 依赖关系

| Dashboard 卡片 | 依赖的数据 |
|----------------|------------|
| 企业数量 | 企业创建接口 |
| 企业状态饼图 | 企业的 `status` 字段 |
| 行业分布 | 企业的 `industry` 字段 |
| 发票数量 | 发票导入接口 |
| 报告数量 | 报告生成接口 |
| 最近企业列表 | 企业创建时间 + 名称 |
| 税务报告率 | 报告数 / 企业数 |

**断点风险**：如果企业创建成功但没有导入任何发票，Dashboard 会显示正确但很空。

## 八、快速检查清单（供你验证代账给的资料）

收到代账的资料后，按这个清单检查一遍，确保流程不断：

### 检查步骤 1：企业信息
- [ ] 有公司名称
- [ ] 有统一社会信用代码（18位）
- [ ] 有纳税人类型（一般纳税人 / 小规模纳税人）
- [ ] 有行业分类

### 检查步骤 2：发票明细
- [ ] 每张发票都有发票号码
- [ ] 每张发票都有开票日期
- [ ] 每张发票都有金额（含税或不含税都行，但最好分开）
- [ ] 发票类型是否标注清楚（进项/销项）
- [ ] 如果进销项混在一个文件，确认有无类型列

### 检查步骤 3：银行流水
- [ ] 每笔交易都有日期
- [ ] 每笔交易都有摘要/说明
- [ ] 每笔交易都有金额（借方或贷方至少一个有值）
- [ ] 确认每个企业单独一个文件

### 检查步骤 4：匹配可行性
- [ ] 发票的价税合计 和 流水的金额 有没有相同的（至少几笔）
- [ ] 相同金额的日期差是否在 7 天以内

## 九、如果代账给的资料有缺失，可以怎么补

| 缺什么 | 怎么补 | 劳动量 |
|--------|---------|--------|
| 缺发票类型列（进/销） | 在 Excel 里加一列，按企业业务特点填入 | 小 |
| 缺税额列 | 用公式计算：金额 × 0.13 （一般纳税人） | 小 |
| 缺销售方名称 | 可以不补，不影响核心流程 | 无 |
| 流水里没有借贷列 | 如果只有一列金额，确认值的正负号意义 | 小 |
| 流水里缺余额 | 可以不补 | 无 |
