# 发票读取 Agent 循环：最小试验

范围：单份已知税局导出格式的采购发票 Excel。独立脚本和隔离 SQLite，不接入现有工作台、不写业务库。

目标是完成原件读取核验，不是生成办理建议。真实模型每轮自主选择一个工具，工具结果保存后成为下一轮输入。不是通过固定脚本依次执行全部步骤。

## 运行方式

在项目根目录运行（使用现有 `.env` 模型配置，产生真实调用费用）：

```sh
.venv/bin/python scripts/invoice_agent_pilot.py output/invoice-agent-pilot/new-run --initialize --steps 2
.venv/bin/python scripts/invoice_agent_pilot.py output/invoice-agent-pilot/new-run --steps 6
```

首条命令从 `data/demo/f.db` 只读取得唯一一份采购发票来源及候选记录，复制原件到隔离目录。第二条命令从 SQLite 恢复进度。目录已存在时拒绝初始化，防止覆盖运行证据。`--corrupt` 仅在初始化时给隔离候选的一条净额增加 0.01，用于故障试验。

模型可以选择：查看来源结构、核验候选、重读原件、分类后续事项、申请完成、暂停。模型不能写 SQL、修改正式账务，也不能用自己的文字把核验改成通过。

每次执行最多指定步数，默认 8 步；默认 900 秒调度预算，单次模型调用最长 180 秒。连续三次相同工具及结果没有进展时暂停。达到本次步数预算保留 RUNNING，可显式续跑；尚未接入后台定时恢复。进程中断可能重复一次只读工具或模型调用，不承诺恰好一次调用或费用。

## 完成条件

- 原件内容哈希保持一致。
- 逐单元格核对发票号码、开票日期、销售方名称和税号、发票状态、净额、税额。
- 单条价税合计等于净额加税额；整表金额和税额与原件合计相符。
- 检查编号数据行完整覆盖、重复行以及所有工作表；本试验只支持已知表头与空模板，未知非空表保持阻断。
- 当前候选与核验证据指纹一致；业务后续事项明确保留。
- 只有以上检查通过，执行器才将结果存入隔离 SQLite 的 checkpoint.result，并标记 COMPLETED。

企业名称、税号和发票号码只在本地核验。模型收到工具摘要、字段名、行号、合计和检查结果，不接收原始身份字段。

## 已运行的证据

本机结果报告在 `output/invoice-agent-pilot/试验结果.md`。normal 和 recovery 两个目录分别保存 SQLite、来源副本、决策轨迹及结果；真实数据目录被 Git 忽略。

正常运行分两次独立进程完成，验证恢复能力。故障运行先由本地确定性检查发现人为注入的 0.01 差异，再由真实模型自主选择重读、复核及完成；首次故障探针不是模型调用。两条路径均有四次真实模型决策。

定向回归：

```sh
.venv/bin/python -m pytest tests/test_invoice_agent_pilot.py -o addopts='' -q
```

11 项测试覆盖：无证据拒绝完成、字段/行/合计验证、金额错误恢复、漏行与错误标识、过期证据拒绝、合计相抵但明细错误、持久化续跑、无进展暂停、脱敏、来源变更拒绝、业务库未改。测试使用本地语料，缺失时跳过；测试中的 reader 明确为 fixture，不算真实模型验收。

## 证据边界与下一步

已经证明：现有确定性工具可以消除这份资料的整表人工核对；真实模型能依据错误反馈选择修复动作，并继续到受控入库。

尚未证明：未知文件格式、扫描件识别、多资料自主调查、业务判断提问、付款匹配、凭证复核交付、生产多租户并发和成本可控性。现有网页不会因此清除待办。

这份 Excel 的核验用确定性程序即可完成；此次试验证明的是 Agent 的动作选择与恢复机制可行，不能证明使用 Agent 比固定工作流更便宜或更优。建议保留确定性能力，将已验证的任务执行循环逐项接入，不据此直接推翻整个系统。
